# Design — Quarto technical blog at `mapuna.github.io`

**Status:** approved (brainstorming), pending spec review
**Date:** 2026-08-28
**Owner:** mapuna (`mapuna_@outlook.com`)

---

## 1. Goals

A personal technical blog published at `https://mapuna.github.io/` that:

- Renders **full LaTeX** math (macros, AMS environments, numbered equations, cross-refs).
- Presents a **single-column, high-readability** reading experience with a light/dark toggle.
- Provides a **blog index** (listing) plus **per-post prev/next navigation**.
- Supports **executable Python** code cells in posts.
- Deploys automatically from source on every push (no built artifacts in the repo).

## 2. Non-goals (v1)

Comments (giscus), analytics, custom domain, webmentions, series/multi-part navigation,
multi-author support, newsletter integration. All are additive later without restructuring.

    location: navbar

  page-footer:

Post directory names are **date-stripped** (`posts/<slug>/`, e.g.
`posts/jpeg-ai-neural-image-compression/`). The date lives in front matter and
drives the listing sort and the prev/next order; it is not in the URL.

`posts/_metadata.yml`:

```yaml
title-block-banner: false
toc: true
freeze: auto            # re-execute a post only when its own source changes
format:
  html:
    css: []
fields: [title, date, description, reading-time, categories]
```

## 6. Math — MathJax v4

- Loaded via the `html-math-method.url` override above. Quarto still injects its own
  MathJax config block (macros, `tex` package options, `tags` for AMS numbering); only the
  loader script is swapped.
- **Site-wide macros** live in `styles/_macros.tex` as a hidden MathJax block, e.g.:

  ```html
  <div style="display:none">
  \(
    \newcommand{\R}{\mathbb{R}}
    \newcommand{\E}{\mathbb{E}}
    \newcommand{\argmin}{\operatorname*{arg\,min}}
  \)
  </div>
  ```

- **Equation cross-references** (`$$ ... $$ {#eq-foo}`, `@eq-foo`) are numbered by Quarto
  itself, not MathJax — so they are robust to the MathJax version. Only in-environment
  line numbering (`\begin{align}` with `\\`) depends on MathJax `tags: ams`.

### Verification plan (gates the v4 choice)

`posts/2026-05-01-colophon/index.qmd` exercises, in one page:
1. an inline use of a `_macros.tex` command (e.g. `$\E[X]$`);
2. a display equation with a Quarto label + a `@eq-` cross-ref in prose;
3. a multi-line `\begin{align} ... \end{align}` block with `\\` line breaks.

`scripts/check_math.py` runs in CI against `_site/` and **fails the build** if it finds:
- unrendered TeX leaked into visible post prose — literal `\begin{align}` / `\newcommand`
  / `\mathbb` text sitting outside `<script>` blocks and MathJax `mjx-container` elements
  (MathJax typesets client-side, so source TeX legitimately stays inside its delimiters;
  the check targets TeX that escaped them, e.g. an unmatched `$$` or an un-injected macro);
- elements with class `MathJax_Error`, `mjx-merror`, or `merror`.

**Fallback:** if v4 proves incompatible with Quarto's numbering/macros, delete the single
`url:` line — Quarto reverts to its bundled, fully-supported MathJax v3.

## 7. Theme & typography

- **Dual theme** → Quarto renders a light/dark toggle in the navbar automatically.
- Custom SCSS (`theme-light.scss` / `theme-dark.scss`) enforces:
  - single column; content measure `max-width: 46rem` (~720px);
  - **serif body** — *Source Serif 4*, fallback `Georgia, "Times New Roman", serif`;
  - **sans headings** — *Inter*, fallback `system-ui, sans-serif`;
  - **mono** — *JetBrains Mono*, fallback `ui-monospace, SFMono-Regular, monospace`;
  - `line-height: 1.65`, comfortable paragraph spacing, restrained link underlines;
  - **justified prose** — `text-align: justify` + `hyphens: auto` on
    `#quarto-document-content p, li` (article bodies only, not UI / listing cards /
    captions / `.post-nav`);
  - right-margin TOC on ≥ `lg`, collapses inline below that;
  - `.post-nav` styling (see §8).
- **Fonts self-hosted** as woff2 under `styles/fonts/`, referenced via `@font-face` with
  `font-display: swap`. No third-party font requests.

**Authoring rule (all posts):** section headings are **Title Case**, compact
professional noun phrases — never sentences or fragments. E.g. "Task-Aware Coding
for Machine Vision", not "Baby-steps to the Ludicrous Idea: …".

### 8a. SEO (on-page)

- `open-graph: true` and `twitter-card` (creator `@mapuna`) in `_quarto.yml` → link-preview cards.
- **Required front-matter field:** every post carries a unique `description` (~150 chars).
  A pre-render lint (extend `scripts/build_manifest.py`) fails the build on a post with no
  `description` or one over 200 chars.
- `site-url` set → Quarto auto-emits `<link rel="canonical">` per page and a
  `sitemap.xml` at the site root. The new site is canonical; migrated posts keep only a
  human-readable "originally published at…" line, **no** `rel=canonical` back to WordPress.
- `robots.txt` at project root: allow all, add `Sitemap: https://mapuna.github.io/sitemap.xml`.
- `styles/jsonld.html` (in `include-in-header`): emits a JSON-LD `BlogPosting` block built
  from `title`, `date`, `description`, `author`, and the page URL. Quarto does not do this
  by default (~20 lines of templated HTML using document metadata).
- Post-deploy manual step: submit `sitemap.xml` to Google Search Console once.
- Descriptive image `alt` text on every figure (also accessibility); full-content RSS.

### Prev/next per post — build-time component

No runtime JS. Ordering logic in one small Python script; injection is a pure Pandoc AST
operation so the block inherits the active theme (incl. dark mode) for free.

**1. `scripts/build_manifest.py`** — registered as `project.pre-render`.
- Walks `posts/*/index.qmd`.
- Parses YAML front matter (`title`, `date`, `draft`); **skips** `draft: true`.
- Sorts ascending by `date`, then by directory name (stable tie-break).
- Emits `_manifest.lua` at project root — a Lua-loadable table (no JSON parsing in the
  filter):

  ```lua
  return {
    { path = "posts/colophon/index.qmd",
      title = "Colophon: how this blog is built",
      href  = "/posts/colophon/" },
    { path = "posts/jpeg-ai-neural-image-compression/index.qmd",
      title = "JPEG AI: Neural Image Compression, Standardized",
      href  = "/posts/jpeg-ai-neural-image-compression/" },
  }
  ```

  Directory names no longer carry the date, so `build_manifest.py` sorts on the
  front-matter `date` field, not the directory name (directory name stays only as
  the final tie-break).

- `href` derived from `path`: strip `index.qmd`, prepend `/`. Root-relative links are
  correct because this is a **user site served at the domain root**. (If the project ever
  moves to a project-pages subpath, prefix with `site-url`'s path.)
- Deps: `pyyaml` (in `requirements.txt`). Runs on both `quarto preview` and CI, so Python
  must be on `PATH` locally too — documented in §11.

**2. `filters/post-nav.lua`** — listed in `_quarto.yml` `filters:`; self-guards.
- Resolve current source path: `quarto.doc.input_file` if available, else
  `PANDOC_STATE.input_files[1]`; normalize to a project-relative POSIX path.
- No-op unless the path matches `^posts/.+/index%.qmd$`.
- No-op (graceful) if `_manifest.lua` is absent — e.g. a bare single-file render with no
  pre-render step.
- Find current entry index `i`. `previous = manifest[i-1]` (older), `next = manifest[i+1]`
  (newer). Omit whichever side does not exist.
- Append to `doc.blocks` a native Div:

  ```
  <nav class="post-nav">
    <div class="post-nav__prev"><span class="post-nav__label">← Previous</span>
      <a href="{prev.href}">{prev.title}</a></div>
    <div class="post-nav__next"><span class="post-nav__label">Next →</span>
      <a href="{next.href}">{next.title}</a></div>
  </nav>
  ```

**3. SCSS** — `.post-nav` is a two-column flex row with a top border and top margin;
`.post-nav__label` is small and muted; the `<a>` is the prominent link. `post-nav__next`
is right-aligned. Below `sm`, the row stacks vertically. When only one side is present it
takes the natural edge (prev → left, next → right).

**Convention:** *Previous = older post, Next = newer post.* Rendered at the **foot** of the
post, after content.

**Edge cases:** first post → only "Next"; last (newest) post → only "Previous"; a single
post → no nav block; `draft` posts never appear as neighbours and get no nav themselves.

## 9. Executable Python

- `freeze: auto` in `posts/_metadata.yml`: a post re-executes only when its own `.qmd`
  changes; otherwise results are restored from committed `_freeze/`.
- Authoring loop: run cells locally, `quarto render`, **commit the updated `_freeze/`**,
  push. CI then restores unchanged posts from cache and executes only new/changed ones.
- `requirements.txt` (initial, grows as posts need):

  ```
  jupyter
  pyyaml
  numpy
  matplotlib
  ```

## 10. CI/CD — `.github/workflows/publish.yml`

- **Trigger:** push to `main`, plus `workflow_dispatch`.
- **Permissions:** `contents: read`, `pages: write`, `id-token: write`.
- **Concurrency:** group `pages`, `cancel-in-progress: false`.
- **`build` job** (`ubuntu-latest`):
  1. `actions/checkout@v4`
  2. `quarto-dev/quarto-actions/setup@v2` (pin `version:` to match local, currently `1.6.42`)
  3. `actions/setup-python@v5` (`3.12`, `cache: pip`)
  4. `pip install -r requirements.txt`
  5. `quarto render` (runs `pre-render` → manifest → filters → `_site/`)
  6. `python scripts/check_math.py _site/`  ← fails build on unrendered TeX / MathJax errors
  7. `actions/upload-pages-artifact@v3` with `path: _site`
- **`deploy` job:** `needs: build`, environment `github-pages`, `actions/deploy-pages@v4`.
- One-time: `gh api` / repo settings → Pages build source = "GitHub Actions".

## 13. Risks & fallbacks

| Risk | Mitigation / fallback |
|---|---|
| MathJax v4 incompatible with Quarto's macro/numbering config | `check_math.py` catches it in CI; remove the `url:` line → bundled v3 |
| Lua filter can't resolve current file path on some Quarto builds | dual lookup (`quarto.doc.input_file` → `PANDOC_STATE.input_files[1]`) |
| `pre-render` Python script missing on an author machine | documented venv step; filter no-ops if `_manifest.lua` absent |
| Root-relative prev/next `href`s break if site moves off domain root | user site is permanent; note in script to prefix `site-url` path if ever moved |
| `_freeze/` not committed after local edits → CI re-executes, needs all libs | keep `requirements.txt` complete; document the commit-`_freeze/` step |
| WordPress images disappear / rate-limit | images vendored into the post directory at import time |
